# 06. Порции S/M/L

Status: ready-for-human
Blocked by: 05

Пользователь выбирает не граммы, а размер: маленькая, обычная, большая. Числа за
ними берём из данных.

## Откуда числа

Основной путь — распределение масс порции внутри группы [[04-canonical-dishes]]:
`kcal(Порции) / kcal(100 г) × 100` по каждому рецепту группы, затем p25 / p50 / p75.

Масса порции есть у 83 462 рецептов из 154 158, и распределение по всему дампу
уже посчитано: медиана 230 г, квартили 143 и 365. Но по **группам** данных будет
резко меньше: 122 256 позиций собраны из одного рецепта, у части из них порции
нет вовсе.

Поэтому три уровня, в порядке убывания доверия:

1. ≥5 рецептов с порцией в группе → квантили группы.
2. 1–4 рецепта → медиана группы как M, а S и L — от категорийных коэффициентов.
3. Порции нет → медиана и квантили по листу `kroshki`; если и там пусто — по
   первому уровню категории (17 значений, все заполнены).

Коэффициенты по категориям считаются из тех групп, где данные есть, — то есть
это тоже из данных, а не выдумка.

## Результат

Три строки `ingredient_portions` на блюдо: `seq` 1/2/3, `label_ru` «маленькая
порция» / «обычная порция» / «большая порция», `is_default = true` у средней.
Новое поле или соглашение о `seq` — на усмотрение реализации, но `is_default`
уже занят FNDDS-семантикой «официальный размер по умолчанию», и она совпадает.

## Критерии приёмки

- У каждого блюда ровно три порции, S < M < L строго.
- Уровень происхождения (1/2/3) записан — без него потом не понять, где число
  из данных, а где из категорийного приора. В аналитике [[11-metrics]] это
  отдельный срез.
- Здравый смысл на 20 известных блюдах: борщ M ∈ 250–400 г, оливье M ∈ 150–250 г,
  блины M ∈ 100–200 г.

## Замечания

**Масса — это сырьё, а не готовое блюдо.** Формула из [[02-measure-regression]]
даёт сумму заложенных продуктов: у супа она завышена на выпаренную воду… точнее,
занижена, если воду в рецепте не указали, и завышена, если указали, а она выкипела.
У выпечки занижена по той же причине наоборот. Проверка на 20 блюдах выше — это
не косметика, а способ поймать систематический сдвиг по категориям. Если он есть,
он лечится категорийным коэффициентом уварки, и это отдельная находка.

L/S ≈ 2.5 по всему дампу (365/143) — многовато для «той же порции побольше».
Возможно, разброс между рецептами это не разброс порций, а разброс того, что
авторы считают порцией. Проверить до того, как показывать числа пользователю.


## Comments

**Сделано** внутри `build_import.py`. Три порции у каждого блюда, `is_default`
на средней, уровень происхождения пишется в данные.

**Уровень 1 (квантили самой группы) получился только у 458 блюд** из 122 607.
У 73 503 своя медиана, но S и L от категорийных коэффициентов (уровень 2);
у 48 646 всё от категории (уровень 3).

Причина — фрагментация из [[04-canonical-dishes]]: для квантилей нужно ≥5
рецептов с порцией в одной группе, а группы вышли мелкими, потому что разные
названия остаются разными позициями. Это прямо бьёт по H8: сравнивать типовой
вес с модельной оценкой имеет смысл в первую очередь на 458 блюдах уровня 1, а
на остальных метрика измерит качество категорийного приора. Срез по уровню в
[[11-metrics]] обязателен, а не желателен.

Категорийные коэффициенты (36 категорий) посчитаны по тем группам, где данных
хватило, то есть тоже из данных.
