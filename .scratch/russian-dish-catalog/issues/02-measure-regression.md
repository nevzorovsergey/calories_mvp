# 02. Восстановление граммовки бытовых мер

Status: ready-for-human
Blocked by: —

В граммах и миллилитрах задано только 34% упоминаний ингредиентов. Остальное —
`шт` (272k), `ст. л.` (160k), `ч. л.` (118k), `стак.` (49k), `зуб.` (28k),
`пуч.` (16k), `щепот.` (10k), `бан.` (10k) и ещё десяток. Сайт пересчитывает их
в граммы, но коэффициент не публикует.

Без этого не считается ни КБЖУ блюда по нашему справочнику, ни его масса, то есть
блокируются обе цели.

## Идея

Масса блюда известна: `M = kcal(Готового блюда) / kcal(100 г) × 100`. Проверено —
на 1693 полностью-граммовых рецептах медиана отношения к сумме граммов ровно
1.000, в ±2% укладываются 78%.

Значит каждый рецепт — это уравнение:

```
Σ_j  qty_j · g(name_j, unit_j)  =  M
```

Неизвестные — граммы одной меры конкретного ингредиента. Уравнений 154 тысячи,
неизвестных на порядок меньше. Разреженный неотрицательный МНК.

## Что сделать

1. Разбор поля `count`: числа с запятой, дроби (`1/2`, `2-1/2`, 43 310 упоминаний
   со слэшем), 128 нестандартных строк («на кончике ножа», «1 + 1/4 стак.»,
   «2\3 стак.») — их в обучение не брать, вынести списком.
2. Известные меры фиксируем, а не решаем: `г`/`гр`/`мл` = 1, `кг`/`л` = 1000.
   Они уходят в правую часть.
3. Пустой `count` («по вкусу», 17% позиций) — отдельная неизвестная на
   ингредиент, не ноль: соль по вкусу вклад даёт.
4. Регуляризация к априорной оценке по мере (`ст. л.` ≈ 15, `ч. л.` ≈ 5,
   `стак.` ≈ 200, `зуб.` ≈ 4), иначе редкие пары уйдут в бессмыслицу.
5. Пары с малым числом наблюдений заменяем априором по мере — коэффициент,
   выведенный из трёх рецептов, хуже, чем разумная константа.

## Результат

`data/povarenok-measures.json` — коммитится.

```json
{ "Яйцо куриное": { "шт": 55 }, "Лук репчатый": { "шт": 95, "": 0 } }
```

Скрипт разовый и оффлайновый, на Python (в проекте нет ни numpy, ни решателей;
tsx-скрипты этим заниматься не должны). Живёт по той же логике, что раунды
перевода: считается вручную, коммитится результат. Импортёр на TS читает JSON.

## Критерии приёмки

- Holdout 10% рецептов: медианная ошибка предсказанной массы блюда ≤10%.
- Здравый смысл на известных величинах — это отдельная проверка, не следствие
  метрики: яйцо `шт` ∈ 45–65 г, лук репчатый `шт` ∈ 70–120 г, чеснок `зуб.` ∈
  3–6 г, мука `ст. л.` ∈ 10–20 г, сахар `ч. л.` ∈ 4–8 г.
- Отброшенные строки перечислены с причинами.

## Замечания

1693 полностью-граммовых рецепта в обучении бесполезны (в них нет неизвестных),
но именно они уже подтвердили формулу массы. Holdout берём случайный из рецептов
с неизвестными.

Восстановленная масса — это сумма **сырья**. Уварка, выпаривание и ужарка в ней
не учтены, и это надо помнить в [[06-portions-sml]]: вес порции супа по этой
формуле завышен на выпаренную воду, а вес котлеты занижен наоборот.

2. **«По вкусу» весит ноль** — измерено, не предположено. Пока эти позиции
   моделировались как неизвестные, они растаскивали массу: яйцо уезжало на 34 г,
   лук на 39 г.
3. **Регрессия эту задачу не решает.** Ни МНК, ни МНК с нормировкой и отсевом
   выбросов, ни покоординатный спуск по медианам. Причина — коллинеарность:
   определена сумма коррелированных ингредиентов, а не слагаемые. Работает
   послойное снятие. Все три тупика описаны в шапке скрипта, чтобы их не
   проходили заново.

Порог `MIN_CONTRIBUTION`: пары, объясняющие меньше 10% остатка, оставлены на
априоре. Метрика от этого стала хуже (было 3.1% по медиане), а коэффициенты —
правдоподобнее: чеснок с 24 г за зубчик вернулся на 4 г. Метрика мерила
сумму, а нужны слагаемые.
