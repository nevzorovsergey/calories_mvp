# Справочник русских блюд и распознавание по названию

Status: needs-triage

## Зачем

Сейчас единица распознавания — ингредиент. Модель смотрит на фото и выдаёт список
позиций с граммами, вся точность живёт на ней, и на ней же стоят H1 и H2.

Меняем единицу на блюдо. Модель отвечает на вопрос «что это?», а не «из чего это и
сколько весит», и отвечает не одним вариантом, а тремя. Состав и типовой вес
приходят из справочника, пользователь выбирает название и размер порции.
КБЖУ считается по нашему справочнику нутриентов (USDA), а не берётся у источника.

Три следствия, ради которых всё затевается:

* Модель перестаёт угадывать граммы отдельных ингредиентов — самая слабая её
  способность (H2 говорит, что основная ошибка именно в весе).
* Пользователь правит не десять строк, а делает два выбора из трёх вариантов.
* Состав блюда становится воспроизводимым: одно и то же блюдо у разных людей
  разбирается одинаково.

## Источник

`data/povarenok/` — 154 158 рецептов с povarenok.ru, срез 2024-02-13 (см.
`data/README.md`, там же откуда качать и что внутри). Ценность источника не в его
КБЖУ — числа считал сам сайт, лабораторных данных за ними нет, — а в трёх вещах:
русские блюда, их раскладка на ингредиенты и распределение масс порций.

## Что уже проверено на данных

Три факта в пользу плана:

1. Словарь ингредиентов закрытый — **1172 названия**, 279 покрывают 95% из 1.38 млн
   упоминаний. Маппинг на наш справочник — задача на тысячу строк.
2. Масса блюда восстанавливается: `kcal(Готового блюда) / kcal(100 г) × 100` даёт
   сумму граммов, посчитанную сайтом. На 1693 рецептах, где всё задано в г/мл,
   медиана отношения 1.000, в ±2% укладываются 78%.
3. Масса порции — медиана 230 г, квартили 143 и 365 (83 462 рецепта). Русские
   порции русских блюд, чего в FNDDS нет.

Три факта против наивных решений — каждый закрывает подход, который выглядел
очевидным:

4. **`recipe_variants_urls` не годится для схлопывания дублей.** 2 млн рёбер, из
   них 1.65 млн несимметричных; связные компоненты дают одну компоненту на
   154 068 рецептов из 154 158. Это блок «похожие рецепты», а не отношение
   эквивалентности.
5. **Нормализация названий тоже не годится.** 135 612 уникальных заголовков →
   131 960 после нормализации и сортировки токенов. 122 256 встречаются один раз.
   Русские рецепты названы индивидуально: «Ласточкино гнездо», «Салат Анастасия».
6. **Граммовки бытовых мер в дампе нет.** В г/мл задано 34% упоминаний, полностью
   в граммах — 1752 рецепта из 154 158. Остальное — `шт` (272k), `ст. л.` (160k),
   `ч. л.` (118k), `стак.`, `зуб.`, `пуч.`, `щепот.`.

Из 4 следует, что дубли схлопываются по названию, а не по графу вариантов. Из 5 —
что схлопнется мало: справочник получится большим (~132k позиций), и вся работа
переносится с дедупликации на **ранжирование** — какие три названия показать.
Из 6 — что пересчёт мер в граммы блокирует обе цели и идёт первым.

## Границы

Не делаем: тексты рецептов и фотографии Povarenok пользователю не показываем
(лицензия — см. `data/README.md`); пошаговые инструкции не импортируем; поиск по
справочнику блюд руками (это отдельная фича, здесь только выдача трёх кандидатов).

## Решения

| Развилка | Решение |
|---|---|
| Как сводим 154k рецептов к позициям справочника | Только по названию. Разные названия остаются разными позициями, даже если состав почти совпадает — «Ласточкино гнездо» и «Котлеты с яйцом» это для пользователя разные ответы на вопрос «что ты сфотографировал» |
| Что делаем с текущим промптом | A/B рядом, `prompt_version = 'v3-dish'`; v1/v2 остаются эталоном для H1/H2 |
| Какие блюда показываем в топ-3 | Общий пул `kind='dish'`, при равном скоре выигрывает Povarenok |
| Где считается регрессия мер | Разовый оффлайн-скрипт на Python, результат коммитится JSON-ом — как `translations.json` |
| Откуда S/M/L | Квантили масс порций внутри кластера, при нехватке данных — категорийные коэффициенты |

## Новая гипотеза

| № | Гипотеза | Как измеряем |
|---|---|---|
| H7 | Пользователю проще выбрать блюдо из трёх названий, чем править список ингредиентов | Доля приёмов пищи, где выбран один из трёх вариантов без ручной правки состава; сравнение с H1 на тех же фото |
| H8 | Типовой вес блюда из справочника точнее модельной оценки массы | MAPE выбранного S/M/L против MAPE `total_weight_g` из v2-scale на тех же фото |

## Фазы

**Ф0 — фундамент данных** (01–03). Без него ни одна из двух целей не считается.
Граммовки бытовых мер и маппинг ингредиентов на наш справочник, плюс сквозная
проверка обоих через КБЖУ источника.

**Ф1 — справочник блюд** (04–06). Канонизация, импорт, порции S/M/L.

**Ф2 — распознавание по названию** (07–11). Промпт, матчинг, схема, интерфейс,
метрики. Начинается только после Ф1: без справочника проверять нечего.
