# Поиск по справочнику отвечает за 800–900 мс

Status: needs-triage

## Что происходит

`search_ingredients` — путь маппинга распознанных ингредиентов. Он вызывается на
КАЖДУЮ позицию блюда, то есть десять ингредиентов складываются в девять секунд
ожидания.

Замер на живой базе (сетевой канал до Огайо — 185 мс, для сравнения
`search_dishes` в том же прогоне отвечает за 280 мс):

| | до правки «ё» | после |
|---|---|---|
| «лук репчатый» | 845 мс | 1006 мс |
| «chicken breast» | 738 мс | 954 мс |
| «куриная грудка» | 815 мс | 1097 мс |

То есть ~800 мс появились ДО правки про «ё» — их принёс импорт 122 607 блюд
Povarenok. Сама «ё» добавила примерно четверть сверху. После индексов из 0013 —
870–930 мс.

## Причина

Триграммный индекс построен по всей таблице, а фильтр по `kind` применяется уже
после чтения строк с диска. EXPLAIN, запрос «куриная грудка» с
`kind = 'ingredient'`:

```
Bitmap Index Scan on ingredients_name_ru_idx … rows=8884
Rows Removed by Index Recheck: 8324
Rows Removed by Filter: 525          ← отсев по kind
Heap Blocks: exact=4042              ← 4042 страницы ради 35 строк
Execution Time: 363 ms
```

Сырья 8265 строк, блюд 128 040. Поиск по сырью вычитывает в шестнадцать раз
больше мусора, чем полезного.

## Что уже проверено

**Частичный индекс решает задачу — 15.9 мс вместо 363**, в 23 раза. Проверено
EXPLAIN'ом с литералом и с константным массивом, оба варианта его берут.

**Но внутри функции он не работает**: `kinds` там параметр, а не литерал, и
планировщик не может доказать предикат частичного индекса. Замер после создания
частичных и составного (`btree_gin` по `(kind, name_ru)`) индексов показал: время
функции не изменилось. Индексы удалены миграцией 0014 как мёртвый груз.

**Не помогло:** дополнительные btree по выражениям ярусов `exact`/`head` — они
уже существовали с миграции 0005, я создал дубликаты и удалил их там же.

## Что делать

Переписать `search_ingredients` с ветвлением по частому случаю
`kinds = array['ingredient']`: в этой ветке предикат становится литеральным,
частичный индекс — доказуемым. Плюс вернуть частичные индексы.

Обязательное условие: замер до и после по реальным запросам из
`recognition_items`, как это сделано для «ё» (см. `.scratch/russian-dish-catalog`,
тикет 08). На этом пути стоят H1 и H2.
