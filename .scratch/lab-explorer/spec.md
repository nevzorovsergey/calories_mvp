# Лаборатория: справочники и разбор по пользователям

Status: ready-for-agent

## Зачем

`/lab` сейчас отвечает на вопрос «какая модель лучше в среднем». Это агрегаты, и
за ними не видно ни одного конкретного случая. Два вопроса, на которые ответить
нечем:

1. **Что вообще лежит в справочнике.** 136 тысяч позиций из четырёх источников,
   и единственный способ на них посмотреть — SQL-редактор Supabase. Когда модель
   говорит «борщ», а маппинг даёт «Soup, borscht, canned», понять, почему так,
   можно только руками в базе.
2. **Что произошло с конкретной фотографией.** Кто загрузил, что ответила
   модель, что человек поправил и почему. Агрегат `MAPE = 34%` не показывает, что
   треть ошибки — это два случая, где модель приняла салатник за пиалу.

Первый вопрос — про справочник, второй — про данные эксперимента. Оба смотрят с
десктопа: таблица на 136 тысяч строк и сетка фотографий в 390 пикселей ширины не
живут.

## Решения, принятые до начала

* **Десктопная ширина.** `/lab` выезжает из группы `(app)` в свою группу
  `(lab)` с отдельным layout: без Konsta-таббара, без `max-w-screen-sm`. URL не
  меняется — существующие тесты и ссылка из профиля продолжают работать.
  Пользовательские экраны остаются мобильными без изменений.
* **Никакой новой разметки.** Вердикт «правильно/неправильно» не заводится
  отдельным полем. Выводится то, что человек уже проставляет своими действиями:
  правки состава (`meal_items.origin`, `meal_removed_items`), выбор блюда из трёх
  кандидатов, и ответы модалки «Откуда вес?» — способ определения веса, звёздочки
  уверенности 1–5, эталоны в кадре, комментарий.
* **Справочник — чтение плюс точечная правка.** Правятся `name_ru`, `category`,
  `is_active`, `is_service` и синонимы. Нутриенты, порции и раскладка — только
  чтение: они приезжают импортом, и правка вручную рассинхронизировала бы их с
  источником. История не переписывается: `meal_items` хранит снимок нутриентов на
  момент сохранения (0001), правка справочника её не задевает.

## Что делаем

### FR-LABX-1 — Оболочка

Группа `(lab)` с гейтом `profiles.is_admin` в layout: одна проверка на весь
раздел вместо копии в каждой странице. Боковая навигация: Метрики, Справочник,
Пользователи, Приёмы пищи.

### FR-LABX-2 — Справочник: список

Поиск и фильтры: вид (сырьё/блюдо), источник, категория, активность, служебность,
есть ли порции / раскладка / нутриенты. Постраничная выдача с общим счётчиком.
Сортировка по популярности, названию, id.

Всё одним RPC `lab_catalog_page`: фильтры, сортировка, страница и `count(*) over ()`
за один заход. Причина та же, что в 0016 — PostgREST развернул бы «есть ли
порции» во встроенный join и посчитал бы его до limit по всей таблице.

### FR-LABX-3 — Справочник: карточка

Нутриенты на 100 г по группам (макро / витамины / минералы), порции с
граммовкой, раскладка на компоненты с долями, синонимы, происхождение
(`source`, `source_id`, `portion_source_level`), и — главное — **где эта позиция
реально всплывала**: в скольких приёмах пищи, в скольких распознаваниях, с каким
`match_status`.

### FR-LABX-4 — Справочник: правка

`PATCH /api/lab/catalog/[id]` — `name_ru`, `category`, `is_active`, `is_service`.
`POST/DELETE /api/lab/catalog/[id]/aliases` — синонимы. RLS-политики на запись
для админа (0017); проверка `is_admin` в маршруте — чтобы вместо пустого ответа
пришла честная 403.

### FR-LABX-5 — Пользователи

Таблица: кто, сколько приёмов пищи, сколько с фотографией, сколько распознаваний,
доля принятых без правок, медиана отклонения веса, сколько раз заполнена модалка
«Откуда вес?», когда последняя активность.

### FR-LABX-6 — Лента приёмов пищи

Фильтры: пользователь, вердикт (принято как есть / поправлено / ждёт выбора /
неудача / вручную), период. Строка ленты — превью, дата, автор, название,
вердикт, отклонение веса и калорий, звёздочки уверенности.

### FR-LABX-7 — Разбор одного приёма пищи

Большое фото, подсказка пользователя, все распознавания с их стоимостью и
латентностью, три кандидата блюда с пометкой выбранного, построчный дифф
«модель → человек» (оставлено / изменено / удалено / добавлено), и ответы модалки
«Откуда вес?» словами, а не кодами.

## Границы

* Метрики на `/lab` не трогаем — они уже считаются и проверены тестами.
* Правка нутриентов, порций и раскладки — нет: см. решения выше.
* Удаление позиций справочника — нет, только `is_active = false`.
